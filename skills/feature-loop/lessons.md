# Feature-loop — meta-leçons cross-projet

Leçons sur *comment piloter la boucle*, valables sur tous les projets (pas les specs d'un projet — ça va dans `project_feature_loop_insights.md`). Chargé à l'init, complété en fin de run et par `learn`.

Format : `- **<titre>** : <règle actionnable> — *vu sur un run réel*`. Additif uniquement.

## Leçons

<!-- (vide pour l'instant — se remplit au fil des runs et via `learn`) -->
- **Re-dériver la preuve d'un devil's advocate qui dit "SURVIVES", ne jamais la croire sur sa confidence** : un juge adversarial peut rejeter (haute confiance 0.85) un finding réel du reviewer principal via une preuve mathématique dont le LEMME est faux. Vu sur un run réel (review-only) : C2 a "prouvé" que typical∈[low,high] en supposant typical_route∈[low_route,high_route] — faux, car la conversion à bases de taux mixtes (Close×rate.Close vs High×rateTypical) sort Close€ de la bande. La mère doit re-dériver le lemme contre le code réel quand un DA contredit le reviewer sur un axe invariant/sécurité, pas arbitrer sur les confidences. — *vu sur un run réel*
- **Désaccord MAJOR-vs-none entre reviewer et devil's advocate = arbitrage par lecture directe du code + magnitude empirique, pas panel** : quand le point est purement technique et vérifiable (une formule, un clamp), la mère tranche plus vite et plus sûrement en lisant les 50 lignes concernées qu'en montant un panel-3. Réserver le panel aux jugements non re-dérivables. — *vu sur un run réel*
- **Pagination : red-check la frontière exacte, pas que la page partielle** : un test de "dernière page" qui n'utilise qu'une dernière page PARTIELLE (`total < offset+pageSize`) ne distingue pas `HasNext: total > offset+pageSize` de `>=` — ils ne diffèrent qu'à `total == offset+pageSize` (dernière page PLEINE). Toujours un cas exact-boundary. — *vu sur un run réel (mutation `>`→`>=` survivait en vert)*
- **Dédup ⨉ pagination sur 2 sources : la fusion fenêtrée naïve est fausse** : retirer un doublon décale la fenêtre au-delà de ce qu'on a fetché de chaque source. À petit volume, full-fetch + merge/dedup/paginate en mémoire est la solution simple *correcte* (cap + warn anti-troncature-silencieuse). — *vu sur compositeSource*
- **Test-writer ∥ reviewer = review sur état périmé** : lancer l'agent de tests et le reviewer aveugle EN PARALLÈLE fait que le reviewer note "Tests=0/bloquant" alors que les tests arrivent en même temps. Séquencer tests AVANT review, OU prévenir le reviewer que des tests sont ajoutés concurremment (sinon un faux major Tests). — *vu sur un run réel (review Opus Tests=4 alors que 14 tests ajoutés en //)*
- **`make generate` "0 updates" ≠ pas régénéré** : le lock `.makegenerate.lock` peut afficher 0 updates ; vérifier que le `*_templ.go` contient bien le nouveau markup (grep) avant de croire le templ à jour. — *vu sur un run réel*
- **[SUPERSEDED — règle raffinée en SKILL §4.5b : `git checkout --` si fichier propre/committé, restauration par chaîne exacte si modifs non commitées ; jamais `cp` (mauvais cwd = fichier resté muté, vu 8.3.2)]** ~~Red-check : restaurer par copie de fichier, jamais `git checkout -- <file>`~~ : en mode in-place avec impl non commitée, `git checkout --` restaure HEAD = efface l'implémentation entière du fichier, pas seulement la mutation. — *vu sur un run réel*
- **Reviewer qui généralise un finding par symétrie ("X a le bug donc Y aussi") : vérifier chaque cible séparément** : sur un run réel le reviewer a étendu un vrai finding (benchmark.js, units minute réels) à un autre fichier qui n'a PAS de vue intraday — moitié vrai, moitié halluciné. — *vu sur un run réel*
- **Red-check sur fichier porteur de modifs non commitées : restauration par chaîne exacte, JAMAIS `git checkout -- <file>`** : le checkout restaure HEAD et efface le travail non commité du même fichier (vécu : un refactor de la même session effacé, FAIL silencieux en aval). Muter via remplacement de chaîne unique et restaurer en réécrivant le contenu original gardé en mémoire. — *vu sur des runs réels*
- **Vérifier la SÉMANTIQUE d'un champ tiers sur des artefacts réels (XML/dumps) AVANT d'implémenter, pas sur le nom du champ** : un champ nommé "OrderClientId" a été pris pour "id client" ; les XML réels du fournisseur montraient que ce champ portait en fait un numéro de COMMANDE (préfixe magasin + compteur), le client étant dans un autre champ. Le run a implémenté 2 itérations sur la mauvaise cible avant que l'user demande de regarder les XML. Leçon : pour tout mapping vers une API tierce, exiger un exemple réel (dump/XML) en INPUT du plan, et y lire la valeur effective de chaque champ — le nom ment. — *vu sur un run réel*
- **DB dev partagée entre worktrees = piège schéma-en-avance au smoke live** : un autre worktree a migré la DB commune en v56 pendant le run ; le serveur frais (sans cette migration) refuse de démarrer (golang-migrate « no migration found for version 56 »). Fix non destructif : copier temporairement (non-commité) le fichier de migration de l'autre branche dans migrations/ (go:embed le ré-embarque au `go run`), lancer le smoke, retirer. Ne PAS surgery le schema_migrations partagé. — *vu sur un run réel*
- **La baseline preflight doit lancer la MÊME suite que le gate (tags intg inclus)** : un échec préexistant découvert seulement au gate force un stash/unstash de diagnostic en pleine boucle (et un `git stash` sans `-u` laisse les tests untracked qui cassent la compile — toujours `-u`). — *vu sur un run réel*
- **Serveur lancé en arrière-plan : sortie vers fichier direct, jamais `| head`/pipe** : les logs restent piégés dans le buffer du pipe tant que le process vit → diagnostic aveugle (17 min perdues sur un bind-retry silencieux qu'une ligne de log montrait dès la 10e seconde). — *vu sur un run réel*
- **Un `//nolint` posé par l'agent d'impl doit être vérifié contre le linter qui FIRE réellement, pas cru sur parole** : sur un run réel, l'agent A a ajouté `//nolint:goerr113` sur des `fmt.Errorf` capitalisés — or goerr113 n'était PAS activé (config = revive), et le vrai flag était `revive:error-strings` (message d'erreur capitalisé/ponctué). Le nolint suppressait un linter inexistant → warning « unknown linter » + l'erreur réelle restait. La mère DOIT lancer le vrai golangci-lint et lire la règle qui fire avant de faire confiance à un nolint. Fix propre ici : un type `T string` implémentant `error` (échappe à error-strings car pas un littéral errors.New/fmt.Errorf) plutôt que suppresser. — *vu sur un run réel*
- **DA « major » sur replay/idempotence d'un event handler ES → re-dériver, souvent minor** : le devil's advocate a classé « ghost-toast au replay » en major. Arbitrage par lecture code : (a) le replay ne produit un toast que si un subscriber SSE est live sur la visite HISTORIQUE pendant le rattrapage (quasi-nul) ; (b) le chemin nominal (toast succès) avait DÉJÀ ce comportement pré-existant — le diff n'introduit pas une nouvelle classe de bug. → minor. Le fix reste cheap et correct (guard `ErrOrderAlreadyExists → return nil` avant les notifs), donc appliqué en iter-2, mais sans bloquer. Règle : un finding replay/idempotence se re-dérive contre « subscriber live au moment du replay ? » ET « le chemin nominal a-t-il déjà ce comportement ? ». — *vu sur un run réel*
- **Garde de périmètre sur l'agent d'impl : `git diff --name-only` post-impl vs scope déclaré** : sur une tâche e2e « test-only / ne pas toucher prod », l'agent A a modifié un `.templ` de prod de sa propre initiative pour rendre la prémisse d'un test vraie (rendre un `data-no-enter-submit` présent). Rattrapé en review, mais coûteux. Un `git diff --name-only` confronté au scope (surtout prod sur tâche test-only) le détecte instantanément, avant le gate. — *vu sur un run réel*
- **Discriminance d'un test > red-check mono-mutation** : un test critique peut passer pour la MAUVAISE raison quand (a) deux défenses se recouvrent (« ceinture+bretelles » : `data-no-submit` form + `data-no-enter-submit` input → retirer un seul ne change rien d'observable) ou (b) la plateforme couvre nativement (un `<dialog>` HTML ferme sur Escape sans aucun JS → un test qui ferme via Escape passe même si le handler app.js est cassé). Avant de croire un test « non-vacant », vérifier qu'il cible le mécanisme SPÉCIFIQUE et qu'aucun chemin redondant/natif ne le ferait passer ; sinon re-cibler (ex: tester `data-href` qui n'a aucun fallback natif). — *vu sur un run réel*
- **Livrable = code de test → la séparation writer≠tester s'effondre** : pas de « test du test ». Agent A écrit les tests, agent B ne s'applique pas, le signal externe = gate live + red-check (muter la vraie chose testée), l'invariant qui reste = reviewer≠writer. Ne pas spawner de méta-test (faux confort). — *vu sur un run réel*
- **Table à lignes créées paresseusement : exiger un test SANS seed sur toute écriture indépendante** : quand une feature ajoute une colonne écrite par un chemin distinct du flux qui crée la ligne (ligne créée seulement par un premier handler, mais la colonne écrite par un autre handler), un `UPDATE ... WHERE clé` no-ope silencieusement sur clé inexistante (0 ligne, pas d'erreur) = perte de donnée invisible. L'intg qui seede toujours la ligne MASQUE le bug. Le reviewer Opus l'a attrapé en notant que l'INSERT n'existait que dans l'autre chemin. Règle : imposer à l'agent B un cas « écriture sur clé vierge prouve la création » (rougit sur UPDATE nu, vert sur UPSERT). — *vu sur un run réel*
