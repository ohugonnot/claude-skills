# Senior-review — meta-leçons cross-projet (comment piloter la revue)

- **Re-run live d'un reviewer = restaurer propre, zéro backup parasite** : pour vérifier un finding, un reviewer a muté `config.js` (port serveur de test) en faisant ses propres `cp config.js config.js.orig` ; il a restauré le fichier mais laissé les `.orig`/`.bak`, que l'orchestrateur a dû nettoyer. git suit déjà le fichier → muter puis `git checkout -- <file>`, jamais de copie manuelle. Vérifier `git status` propre en fin de revue. — *vu sur un run réel*
- **2ᵉ passe indépendante (senior-review après feature-loop) : valeur prouvée** : sur un module e2e déjà revu une fois par feature-loop, la passe senior-review a trouvé des trous de discriminance ratés au 1er tour (fallback Escape qui ferme un `<dialog>` nativement → test non-discriminant). La review unique sature ; une 2ᵉ passe aveugle, focalisée « ce test rougirait-il vraiment ? », rattrape. Ne pas décourager le multi-passes sur le code qui compte. — *vu sur un run réel*

- **Flag bool propagé en chaîne (handler→source→repo→SQL) : muter chaque COUTURE, pas chaque couche** : les tests par couche peuvent tous être verts (stub handler respecte le flag, intg teste le SQL une fois le flag posé) alors que la transmission entre deux couches est invisible — `HideProcessed: hideProcessed` muté en `false` dans la source survivait à toute la suite unitaire, idem la branche `pageURL` qui re-injecte le flag dans les liens de pagination. Pour tout paramètre traversant N couches, red-check la propagation à chaque jonction. — *vu sur un run réel (2026-06-10)*
- **Routage par clé (sharding/partition/aggregate-id/tenant/topic) : un test qui court-circuite la résolution par clé ne le teste pas — exiger ≥2 entités clés** : trouvé en 2ᵉ passe (sceptique-tests), confirmé par mutation. Un e2e prétendait valider un déblocage d'un cas de routage spécifique au domaine (A ouvre / B clôture / slot de A libéré), mais l'adapter passait UN SEUL agrégat en direct au handler ; or le handler ne gardait que sur la clé locale, le routage par entité se faisant au niveau gateway (la clé d'agrégat). Le bug ne touchant que la clé de routage, l'assertion d'effet "slot libéré" passait quelle que soit l'entité — seule une assertion d'event intermédiaire l'attrapait. Vérifier aussi que l'assertion d'EFFET final est elle-même discriminante (mutation : bug + assertion intermédiaire neutralisée → doit rougir), pas seulement une pré-assertion sur l'input. Méfiance sur les titres/commentaires de test qui disent "exercises the production wiring". — *vu sur un run réel (2026-06-09)*
