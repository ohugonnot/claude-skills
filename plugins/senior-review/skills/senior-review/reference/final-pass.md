# Passe finale sur un autre modèle

**Passe finale sur un autre modèle, avant un verdict `approve`.** Dès que trois relecteurs ou plus du **même** modèle sont passés sur un lot, un tour de plus dans cette monoculture ne rapporte presque rien : ils partagent les mêmes angles morts que l'auteur quand l'auteur est un modèle. Une seule passe sur un modèle différent, en aveugle, a rapporté du réel à chaque fois qu'elle a été tentée. **Modèle de cette passe : Opus par défaut**, le tier max, différent des relecteurs Sonnet. C'est vrai même si Opus a écrit le code : ce qui compte ici, c'est de sortir de la monoculture des relecteurs. **Fable n'est jamais choisi par défaut.** Sur un run réel, la passe finale sous Fable a coûté 181 k tokens et 50 min, plus de deux fois un relecteur. Fable reste réservé aux décisions à fort enjeu : un plan, une architecture, un arbitrage qui engage la suite. Si le skill juge vraiment qu'une passe Fable s'impose ailleurs, il **demande la permission** avant (`AskUserQuestion`), en donnant la raison et le coût estimé. Sans accord explicite, c'est Opus. Seule exception : un `--model fable` donné par l'utilisateur vaut accord. Mécanique : un appel `Agent` avec `model` explicitement différent de celui des relecteurs précédents, un contexte vierge, le diff complet, la liste de ce qui est **tranché ou prouvé** pour qu'il ne re-litige pas — et surtout **aucune liste de pistes**, puisque énumérer plafonne. Lui demander de terminer par « ce qui m'a surpris sans que j'en fasse un finding » : quand plusieurs relecteurs sont déjà passés, c'est là qu'est le signal restant. Ses affirmations factuelles se vérifient comme les autres : sur un run réel, deux de ses sept surprises venaient d'une comparaison contre une référence git périmée.
