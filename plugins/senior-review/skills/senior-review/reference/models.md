# Modèles et exécution des agents

**Dimensionnement modèles** : orchestrateur = le modèle de la session (le plus capable disponible — Opus, Fable… ; synthèse, arbitrage). Reviewers dimension = tier standard (Sonnet ; correctness/sécu escaladent au tier max si `--deep` ou scope sensible). Refuteurs panel = tier standard, sur un **modèle différent de celui du reviewer initial** : le paramètre `model` du tool Agent l'obtient directement (`sonnet`, `opus`, `haiku`, `fable` au mapping courant), indépendamment du modèle de la session — seul un `subagent_type: fork` ignore l'override et hérite du parent. À défaut de modèle disponible, le prompt reformulé et l'ordre inversé cassent au moins le biais de position. Tâches mécaniques (récup ticket, extraction conventions) = tier rapide (Haiku). **Fable comme agent délégué** : seulement pour un plan ou une décision à fort enjeu. Tout autre usage se demande d'abord à l'utilisateur, avec le coût estimé, sauf `--model fable` explicite. Le choix par défaut est Opus (voir « Passe finale sur un autre modèle »). **Les noms = mapping courant des tiers rapide/standard/max** — sur une génération plus récente, lire par tier, pas par nom (paramètre `model` du tool Agent).

**Modèle choisi au lancement** : `--model <haiku|sonnet|opus|fable>`, ou le même mot seul dans la phrase (« /senior-review opus en boucle » ; un chemin existant du même nom reste une cible), fixe le `model` de tous les relecteurs de dimension, à tous les tiers et à chaque tour de boucle. Il prime sur l'escalade de `--deep`, qui garde ses dimensions et son panel. L'orchestrateur reste sur le modèle de la session, les tâches mécaniques sur Haiku. Les refuteurs et la passe finale (Étape 6) tournent sur un modèle **différent** du modèle choisi. Si c'est le modèle de l'auteur connu du code, le dire au rapport : le choix de l'utilisateur prime, l'aveuglement y perd.

**`blind-reviewer` absent des types du tool `Agent`** (skill installé seul, par lien sur son dossier) : proposer une fois à l'utilisateur `ln -s <skill>/../../agents/blind-reviewer.md ~/.claude/agents/`, relire avec `general-purpose` en attendant et le dire au rapport.

**Fan-out par `Workflow`** : si le tool `Workflow` est disponible, le fan-out PEUT passer par un script Workflow (un `agent()` par dimension avec `schema` JSON imposé sur le format finding) — sorties validées structurellement, retries de parsing éliminés. L'interactif (AskUserQuestion) reste en conversation principale, jamais dans un workflow.
