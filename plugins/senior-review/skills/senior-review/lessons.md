# Senior-review — meta-leçons cross-projet (comment piloter la revue)

- **Re-run live d'un reviewer = restaurer propre, zéro backup parasite** : pour vérifier un finding, un reviewer a muté `config.js` (port serveur de test) en faisant ses propres `cp config.js config.js.orig` ; il a restauré le fichier mais laissé les `.orig`/`.bak`, que l'orchestrateur a dû nettoyer. git suit déjà le fichier → muter puis `git checkout -- <file>`, jamais de copie manuelle. Vérifier `git status` propre en fin de revue. — *vu sur 1 run (runs réels)*
- **2ᵉ passe indépendante (senior-review après feature-loop) : valeur prouvée** : sur un module e2e déjà revu une fois par feature-loop, la passe senior-review a trouvé des trous de discriminance ratés au 1er tour (fallback Escape qui ferme un `<dialog>` nativement → test non-discriminant). La review unique sature ; une 2ᵉ passe aveugle, focalisée « ce test rougirait-il vraiment ? », rattrape. Ne pas décourager le multi-passes sur le code qui compte. — *vu sur 1 run (runs réels)*

- **Flag bool propagé en chaîne (handler→source→repo→SQL) : muter chaque COUTURE, pas chaque couche** : les tests par couche peuvent tous être verts (stub handler respecte le flag, intg teste le SQL une fois le flag posé) alors que la transmission entre deux couches est invisible — `HideProcessed: hideProcessed` muté en `false` dans la source survivait à toute la suite unitaire, idem la branche `pageURL` qui re-injecte le flag dans les liens de pagination. Pour tout paramètre traversant N couches, red-check la propagation à chaque jonction — y compris quand la couture vient d'être CRÉÉE par un refactor de signature dans la même session (la couture neuve naît sans test : confirmé par mutation survivante sur source→repo (flag de filtre)). — *vu sur 2 runs (runs réels, run réel 2026-06-11)*
- **Revue de repo entier (URL, pas de diff) : spec-alignment devient docs-alignment, et le receipt le moins cher est la mutation ciblée** : sans ticket, l'oracle de la dimension spec est le README — chaque promesse (seuils, options, plateformes) se vérifie par grep/exec en secondes et rapporte des findings à confiance haute. Pour les gaps de tests allégués, UNE mutation sur un bras de `case` non couvert (suite reste verte → gap prouvé) coûte 30 s et vaut tous les raisonnements. Sur un clone jetable /tmp, la mutation est sans risque pour le working tree de l'user. — *vu sur 1 run (claude-code-statusline, 2026-06-10)*
- **Signature de composant partagé étendue → auditer TOUS les call sites, pas celui de la feature** : ajouter des paramètres (notOrdered/total) à un composant templ réutilisé fait compiler les autres call sites avec des zéros littéraux — la bannière ET le hidden input conditionnels ne s'affichent jamais sur ces chemins, transformant le garde serveur en cul-de-sac 409 sans échappatoire. 3 reviewers l'ont trouvé indépendamment via `grep -rn 'NomDuComposant('` ; le receipt coûte une ligne. Règle : toute extension de signature → grep des call sites + vérifier que chacun peut fournir la vraie donnée (sinon le gap est un finding, pas un détail). — *vu sur 1 run (runs réels)*
- **Un fix suggéré par un reviewer n'est PAS vérifié — l'appliquer puis lancer la suite COMPLÈTE, pas la ciblée** : un nit design plausible (« remplace la boucle par le lookup O(1) idiomatique du même fichier ») cassait silencieusement les produits synthétiques des tests (le lookup dépendait d'une map interne peuplée seulement au registre) ; les tests ciblés du fix étaient verts, seul `go test ./...` l'a attrapé. Le verification_plan d'un reviewer vérifie le FINDING, jamais le FIX proposé. — *vu sur 1 run (run réel 2026-06-10)*
- **Routage par clé (sharding/partition/aggregate-id/tenant/topic) : un test qui court-circuite la résolution par clé ne le teste pas — exiger ≥2 entités clés** : trouvé en 2ᵉ passe (sceptique-tests), confirmé par mutation. Un e2e prétendait valider un déblocage cross-vendeur (A ouvre / B clôture / slot de A libéré), mais l'adapter passait UN SEUL agrégat en direct au handler ; or le handler ne gardait que sur `VisitUUID`, le routage par vendeur se faisant au niveau gateway (`AggregateID == SellerEmail`). Le bug ne touchant que l'email, l'assertion d'effet "slot libéré" passait quel que soit le vendeur — seule une assertion d'event intermédiaire l'attrapait. Vérifier aussi que l'assertion d'EFFET final est elle-même discriminante (mutation : bug + assertion intermédiaire neutralisée → doit rougir), pas seulement une pré-assertion sur l'input. Méfiance sur les titres/commentaires de test qui disent "exercises the production wiring". — *vu sur 1 run (runs réels)*
- **Clé de map dérivée d'un champ "identifiant" supposé unique : exiger le test de collision** : un handler a remplacé une clé unique-par-position (`Produit N`, idx) par une clé sémantique (`Titre - RéfLNA`) ; deux items même titre+réf → overwrite silencieux dans la map = perte de données. Même si la collision est improbable en prod (réf réputée unique), c'est une RÉGRESSION vs l'unicité-par-position antérieure et le fix (suffixe index si clé existe) coûte 3 lignes. Receipt : test 2 items mêmes clés → attendre 2 entrées (rougit à 1 sans le fix). — *vu sur 1 run (run réel)*
- **`json.Marshal` d'un struct avec slice : initialiser la slice à `make([]T,0)` pour produire `[]` pas `null`** : une garde `if summary != ""` sur le retour de Marshal est toujours vraie (Marshal d'un struct scalaire ne rend jamais ""), et une slice nil sérialise en `null` → tout consommateur JS `.map()` plante. Deux nits gratuits souvent liés. — *vu sur 1 run (run réel)*
- **Wrapper mince qui délègue : tester le délégué ne protège PAS le forwarding des arguments du wrapper** : 11 sous-tests couvraient `MissingMeasuresResolved` et la sémantique When du délégué `MissingMeasures`, mais TOUS appelaient le wrapper avec `optionGroups=nil` — muter le forwarding (`optionGroups`→`nil` dans la délégation) survivait à la suite entière du repo. Généralisation de la leçon « flag propagé en chaîne » : pour tout wrapper, muter CHAQUE argument forwardé (le remplacer par sa zero value) ; si la suite reste verte, le contrat de transmission est un angle mort. Receipt en 30 s. — *vu sur 1 run (run réel 2026-06-11)*
- **Assert slice-exacte = forwarding protégé, même si l'argument ne varie jamais dans la table** : un reviewer tests a flaggé « important » que les spy tests ne varient jamais SellerEmail/ValidatorEmail (toujours non-vides) → « la mutation call-site sans cet argument passerait invisible ». Faux : l'assertion compare la slice COMPLÈTE attendue ; omettre l'argument au call-site change la sortie → rougit (receipt : mutation exécutée, FAIL immédiat). Ne pas confondre « input jamais varié » (couvre le filtre, déjà unit-testé ailleurs) et « forwarding non protégé » (couvert par l'exact-match). Receipt 30 s avant de promouvoir ce genre de finding. — *vu sur 1 run (run réel 2026-06-11)*
