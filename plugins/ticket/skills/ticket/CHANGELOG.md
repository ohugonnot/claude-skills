# CHANGELOG — ticket

- **1.0.0** (2026-10-29) : Version publique initiale. Un chemin du milieu entre « je code moi-même » et l'équipe d'agents de `feature-loop` : lire le ticket et le code qu'il touche, plan par un agent fort, test rouge au plus près du réel (e2e dans le harnais du projet, captures mobile/tablette/desktop par profil d'appareil), exécution TDD déléguée, vérification par la session principale (gate, mutation inverse, application relancée), `/senior-review --loop` jusqu'à un tour sans modification, puis une rétrospective de 3 lignes au plus que l'utilisateur valide. Les skills voisins (`issue-mr`, `senior-review`, `branch-wrap-up`, `feature-loop` pour son script de sonde) sont utilisés s'ils sont installés, avec un repli écrit sinon.
- **1.1.0** (2026-10-29) : Revue au tier standard sur le modèle standard quand rien n'est précisé, coût annoncé avant toute revue plus chère. Arrêt de boucle sur le delta de production : un delta de tests seuls ne clôt que si une mutation exécutée prouve sa valeur. « Comme d'hab » enchaîne sans validation mais garde la cadence écran par écran. Ajouts : ticket lu avec ses commentaires, preuve d'absence avant de créer une surface, défaut proposé avec son coût de retour, doubles fidèles au vrai client, deux branches d'un repli, capture manquante = échec, gate qui compte ce qu'elle exerce, mutation restaurée par `cp` (jamais `git checkout` sur un fichier non commité), écran jumeau, relecteurs en lecture seule, tour « mode d'emploi », branche et MR vérifiées avant commit et push, rétro anonymisée.
