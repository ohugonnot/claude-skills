# Changelog — branch-wrap-up

- **1.1.0** (2026-06-10) — **Interop pipeline (audit de synergie famille)** : (1) cible de review adaptée à l'état de l'arbre — working tree si modifs non commitées, sinon `--base <cible>` (sinon senior-review répond « cible vide » et la branche n'est jamais relue) ; (2) review de feature-loop même session reconnue comme équivalente → proposer `--no-review` (pas de double review) ; (3) arbre propre + branche en avance (feature-loop auto-commit ou commits manuels) → sauter l'Étape 3, direct push/MR-PR (pas de double commit) ; (4) routage Étape 0 : branche protégée ou WIP hors-sujet → rediriger vers `issue-mr` ISOLER (frontière isolation/clôture explicitée) ; (5) dédup mémoire étendue aux insights écrits par feature-loop dans la session. Bump minor (comportements de routage nouveaux).
- **1.0.0** (2026-06-10) — **Refonte alignée sur la famille claude-skills** (feature-loop / senior-review / issue-mr) : frontmatter conforme (`description: >` anglais avec patron `NOT for X (use Y)`, `argument-hint`), versioning + CHANGELOG, corps en français avec Étapes numérotées et logs `[xxx]`. La review n'est plus faite par le skill lui-même (self-review, checklist Go hardcodée) : **déléguée à senior-review** (tiers `--quick`/`--deep` pass-through), fallback agent aveugle. Conventions reprises d'issue-mr : détection plateforme glab/gh, branche cible découverte (CLAUDE.md → `git remote show origin`), format de commit `type(scope)` avec scope déduit de `git log -30`. Détection `no_auto_commit`, AskUserQuestion groupée commit+push+MR/PR, délégation de lecture des gros diffs. La capture de connaissances (CLAUDE.md + mémoire) reste la valeur ajoutée propre du skill. Bump initial versionné (remplace la version non versionnée de mars 2026).
